# Hasamex Round 2 — 7–8 Minute Demo Script

## 0:00–0:40 — Introduction
"Hi, I'm Anirudh Bansal. This is my technical case study for the Hasamex AI Engineer role.

The objective was to build a simple application that analyses three expert-call transcripts and answers an interview guide while preserving exact evidence and timestamps.

The main challenge I focused on was not just generating an answer, but making every important answer traceable back to the source transcript."

## 0:40–1:25 — Problem understanding
"The application needs to do five main things: answer the interview guide, extract exact quotes, show timestamps, identify common themes and differences, and allow questions across all three interviews.

The source data represents three markets: France, Germany and the United Kingdom."

## 1:25–2:10 — Approach / architecture
"My approach was to first parse each transcript into evidence segments.

Each segment retains the expert, role, market, timestamp, speaker and source file. I then retrieve the most relevant evidence for a user's question and pass only that evidence to the language model for synthesis.

This makes the evidence trail explicit and also gives me a clear way to reduce hallucinations."

Show the Architecture tab.

## 2:10–2:45 — Tech stack
"The application is built in Python with Streamlit for the interface. I use the OpenAI Python SDK for the language-model step. I use a transparent retrieval layer for this small case so that I can easily inspect why a particular evidence segment was selected.

For a larger dataset, I would move to embeddings and a vector database while keeping the same metadata and citation model."

"These are findings from the supplied interviews, not claims that these three people represent every hospital in those countries."

## 5:45–6:35 — Accuracy / hallucination prevention
"My most important accuracy decision was to avoid allowing the model to freely invent an answer.

The model receives retrieved transcript evidence and is instructed to use only that evidence. Expert, market and timestamp metadata are preserved. Exact quotes shown in the UI are read directly from the source data.

If there is not enough evidence, the application should say so instead of fabricating a response.

For a production system I would also add automated citation-accuracy tests, unsupported-claim detection and a larger evaluation set."

## 6:35–7:10 — Scaling
"For 30 or more transcripts, I would replace the small transparent lexical retriever with an embedding-based vector index. Each chunk would retain the same metadata, allowing filtering by market, expert and interview. I would retrieve a small top-k evidence set and then generate the answer from that evidence."
